# Open questions

Only decisions not settled by `CODEX_SPEC_Unfrozen_Schemas_v4.md` belong here.

1. **Repository licence:** Which software licence should govern the source, and should research
   artifacts or benchmark materials use separate terms?
2. **Phase I model stack:** Which named open-weight 1-2B base checkpoint, exact revision, tokenizer,
   quantisation posture, LoRA targets, and compatible licences will be frozen for Phase I?
3. **Numeric primary-gate configuration:** What preregistered thresholds, confidence-interval rules,
   language-retention tolerance, and anomaly/exclusion rules instantiate G1-G6 before treatment
   runs?
4. **Frozen seed sets and compute budget:** Which exact Phase I seeds (at least three), optimisation
   budgets, and consumer-GPU reference configuration will be preregistered?
5. **Benchmark content and validation:** Which newly authored items, target-domain families, human
   validation protocol, release split, and licensed external diagnostics will constitute frozen
   `v1_core`?
6. **Dirty-tree scientific-run policy:** Must all pilot and confirmatory results originate from a
   clean tree, or may explicitly dirty runs be retained as exploratory-only evidence?
7. **Compatibility materiality boundary:** What canonical fingerprint and review rule determines
   whether a proposed Phase II stack change requires a new compatibility calibration when the
   listed components change only partially?
