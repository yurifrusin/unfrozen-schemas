# Open questions

Only decisions not settled by `CODEX_SPEC.md` belong here.

1. **Repository licence:** Which software licence should govern source code, and should original documentation, benchmark materials, and released data use separate terms?
2. **Phase I primary stack:** Which exact open-weight 0.8–2.2B text-only base checkpoint, revision, tokenizer, LoRA targets, and licence will M2.5 approve as `QUALIFIED_PRIMARY` on the RTX 5070?
3. **Replication stack:** Which transparency-oriented or larger QLoRA candidate will be retained as the declared replication or fallback stack?
4. **Numeric primary-gate configuration:** What preregistered thresholds, confidence-interval rules, language-retention tolerance, and anomaly/exclusion rules instantiate the Phase I hard gate?
5. **Frozen seeds and compute budget:** Which exact Phase I seeds, optimisation budgets, sequence envelope, and workstation runtime ceiling will be preregistered?
6. **Benchmark content and validation:** Which newly authored items, target-domain families, human-validation protocol, private/public split, and licensed external diagnostics constitute `v1_core`?
7. **Dirty-tree scientific-run policy:** Must all pilot and confirmatory results originate from a clean tree, or may explicitly dirty runs be retained as exploratory-only evidence?
8. **Compatibility materiality boundary:** What canonical fingerprint and review rule determine whether a Phase II change requires a new compatibility calibration?
9. **Durable artifact archive:** Which external archive will hold large legally distributable checkpoints, run artifacts, and release manifests, and when should Zenodo or another DOI-backed archive be introduced?
10. **Human validation governance:** Does benchmark validation require institutional ethics review or another documented determination before recruiting external validators?

Resolved operational decisions belong in `PROJECT_HISTORY.md`; evolving scientific rationale belongs in `RESEARCH_LOG.md`.
